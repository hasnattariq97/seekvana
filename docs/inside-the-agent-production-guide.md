# Inside the Agent — Production Guide

Working reference for producing the **120 articles** of Seekvana's flagship agentic path via the `seomachine` workspace's `/produce` → `/deploy` pipeline, and for wiring each one into Seekvana once it lands.

The **Objective & Differentiator** column is the content brief — *what* the article teaches and *what it beats competitors on*. Feed it to seomachine alongside the `/produce` topic string so Stage 4 (Article Planning) never has to guess the angle. The per-module `seomachine/briefs/module-1X.md` files expand each row into a full `/write` block (keywords, audience, angle, cover prompt).

**Source curriculum:** `agentic_ai/Seekvana_Agentic_Engineer_Curriculum.md` (13 modules, trimmed 133 → 120 in production — see Trims note at the end). Path definition: `src/content/paths/inside-the-agent.json` (modules `14`–`26`).

**The flagship thesis (must survive into every article):** teach *universal* agent concepts (RAG, MCP, memory, planning, multi-agent, evals, deployment) **inside the tools professionals actually build with — Cursor + Claude Code + the Claude Agent SDK.** Every lesson ends in a hands-on lab performed in a real editor, not a notebook. Where a lesson needs terminal/Python/Git/APIs/DBs it **cites Getting Started**; where it needs prompt fundamentals it **cites Beyond the Prompt** — we cite, we don't repeat.

**Voice stack (v2 — this path only).** Inside the Agent uses the **v2** seomachine context stack: `brand-voice-v2.md` (one voice, six archetypes), `opening-formula.md` (extractable answer in ~60 words + section-level answers), `author-identity.md` (**named-human byline, not `Seekvana`**), `writing-examples-v2.md`, `style-guide-v2.md`, `seo-guidelines-v2.md`, `launchpad-lesson-format-v2.md`. Every brief block is tagged `[PATH LESSON — Inside the Agent]`, which makes `/write` auto-select this stack. Two consequences that show up in QA below: a **named human author** (Seekvana is the *publisher*), and **structure varies by archetype** (don't force every lesson into the Explainer skeleton).

## Post-deploy QA checklist

Run after **every** `/deploy [slug] [images-folder]`, before the next article. seomachine has shipped these exact bugs on real Seekvana articles.

1. **`faqs` frontmatter keys** — each entry uses `q`/`a`, not `question`/`answer`. Wrong keys silently break the FAQPage JSON-LD (no build error, just missing SEO markup).
   ```yaml
   faqs:
     - q: "..."
       a: "..."
   ```
2. **Frontmatter matches the v2 schema exactly** — `title, description, pillar: "agentic-ai", slug, difficulty, readTime, author: "Hasnat Tariq", authorSlug, publisher: "Seekvana", publishedAt, lastUpdated, tags, featured`, **plus** `lessonModule` + `lessonNumber` set to this article's topic id in `inside-the-agent.json` (e.g. `lessonModule: "14"`, `lessonNumber: "14.01"`). **▲ v2: `author` is the named human, not `Seekvana` — `Seekvana` moves to `publisher`; add `authorSlug` + `lastUpdated`** (see `author-identity.md` / `style-guide-v2.md`). Modules are `14`–`26` — outside both `getting-started.json` (`00`–`10`) and `beyond-the-prompt.json` (`11`–`13`) — so `buildLessonArticleMap()` (`src/lib/mdx.ts:185`) auto-links the article into the path with **no JSON edit**. A wrong `lessonNumber` breaks the link or collides with another path's topic.
3. **Default pillar is `agentic-ai`** for every lesson unless the row's *Hand-off* column names another (a few SDK/deployment/eval lessons live more naturally under `building-with-ai`). The pillar only sets the `/library/<pillar>/<slug>` URL; the path link is driven by `lessonNumber`, so either pillar works — just be consistent and match the cover-image folder.
4. **MDX string-prop rules** — every custom component (`Tip`, `Note`, `Warning`, `Steps`/`Step`, `Mermaid`, `Quiz`, `ArticleImage`, `FAQ`, etc.) receives **only named string props** — no arrays, numbers, or `{children}`. Arrays → `|||`-delimited string; numbers → string (`correct="1"`); charts → `chart="..."`. Breaks silently in `next-mdx-remote/rsc` in prod while fine in dev — surfaces only at `npm run build`.
5. **Difficulty matches the tier** in the tables below.
6. **Images** — cover has **no** caption; every inline `<ArticleImage>` **must** have `caption="..."`. Add `cover.webp` at `public/images/articles/agentic-ai/<slug>/cover.webp` (the prebuild auto-generates the OG `cover.jpg`). Every table has a **bold title on the line above it**.
7. **★ Differentiator survives** — on ★-flagged rows, confirm the current-as-of-2026 angle (CodeAct, MCP OAuth, context rot, the lethal trifecta, deterministic hooks, the harness pattern, pass^k, etc.) is actually present and not flattened into a generic template. This is why the flagship beats the paywalled/intermediate competitors — it must not get dropped.
8. **Environment-native check** — the lab is performed in **Cursor and/or Claude Code**, not described abstractly, and the correct **backlink** (Getting Started / Beyond the Prompt) is present where the *Prereq/Backlink* column names one.
9. **▲ v2 voice checks** — (a) an **archetype was chosen deliberately** (not defaulted to Explainer — see the archetype map in each `module-1X.md` brief); (b) a direct, **extractable answer lands in the first ~60 words** and **every H2 opens with a one-sentence direct answer** (`opening-formula.md`); (c) a **named-human byline + `lastUpdated`** are visible near the top and **Person + Organization + Article + FAQPage JSON-LD** are emitted (author → Person `@id`, publisher → Org `@id`); (d) at least one **genuine first-hand experience sentence** is present — not "in our experience" filler.
10. **Build check** — `npm run build`. Fix anything it flags before the next article. No JSON edit needed.

**Legend:** ★ = flagship-signature lesson (current/under-taught; protect the angle). *Prereq* ids reference other rows in this guide. *Backlink* = an existing Seekvana path to cite for a prerequisite. *Hand-off* = a library pillar the closing "go deeper" link points to.
